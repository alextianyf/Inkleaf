## 01 基本思路

查字典时，没有人从第一页开始翻。你会先翻到中间附近，看要找的词在这一页*之前*还是*之后*，然后把不可能的那一半丢掉。**二分查找**就是把这个习惯精确地写下来：每比较一次，有序列表中可能包含答案的部分就减半。

> [!NOTE]
> 二分查找只适用于已经排好序的数据。排序本身比一次查找更费时，所以同一个列表要被反复查找时才划算。

### 为什么减半这么快

每一步至多保留剩余元素的一半。$k$ 步之后至多剩下 $n / 2^k$ 个元素，因此当 $2^k \geq n$ 时查找结束：

$$
k = \lceil \log_2 n \rceil
\qquad\Rightarrow\qquad
\log_2 1\,000\,000 \approx 20
$$

一百万个元素只需二十次比较，而顺序查找最坏要比较一百万次。

## 02 算法

循环用两个下标框住目标可能所在的区间：

- `lo`，仍在候选范围内的第一个下标；
- `hi`，仍在候选范围内的最后一个下标；
- `mid`，两者的中点，每一轮重新计算。

```python
def binary_search(items: list[int], target: int) -> int:
    """在有序列表中返回 target 的下标；找不到时返回 -1。"""
    lo, hi = 0, len(items) - 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if items[mid] == target:
            return mid
        if items[mid] < target:
            lo = mid + 1  # 目标只可能在右边
        else:
            hi = mid - 1  # 目标只可能在左边

    return -1
```

> [!IMPORTANT]
> **循环不变式**：只要目标在列表里，它就一定位于 `lo` 和 `hi` 之间。循环里的每一行，都是为了让这句话始终成立。

#### 为什么循环条件是 `lo <= hi`

当 `lo` 等于 `hi` 时，还剩恰好一个候选元素，而且它还没被检查过。若写成 `lo < hi`，就会把它漏掉。

> [!CAUTION]
> 把 `lo = mid + 1` 写成 `lo = mid` 看似无害，却可能死循环：当 `lo` 和 `hi` 相邻时，`mid` 等于 `lo`，区间再也不会缩小。每次都要**跳过**刚刚排除的下标。

| 步骤 | `lo` | `hi` | `mid` | `a[mid]` | 判断              |
| ---: | ---: | ---: | ----: | -------: | :---------------- |
|    1 |    0 |    8 |     4 |       21 | 21 < 26，向右     |
|    2 |    5 |    8 |     6 |       30 | 30 > 26，向左     |
|    3 |    5 |    5 |     5 |       26 | 在下标 5 **找到** |

三次比较，而顺序查找需要六次。注意第 3 步时区间已经缩到只剩一个元素——这正是 `lo <= hi` 这个条件要保护的情况。

## 04 代价

|  元素个数 $n$ | 顺序查找（最坏） | 二分查找（最坏） |
| ------------: | ---------------: | ---------------: |
|            10 |               10 |                4 |
|         1,000 |            1,000 |               10 |
|     1,000,000 |        1,000,000 |               20 |
| 1,000,000,000 |    1,000,000,000 |               30 |

输入扩大一千倍，比较次数只多了大约十次。这就是 $O(\log n)$ 在实际中的含义。

> [!TIP]
> 心算步数的方法：数一数 $n$ 能连续减半多少次才到 1。一千个元素：500、250、125、63、32、16、8、4、2、1——十次。

## 05 边界情况

##### 空列表

`len(items) - 1` 等于 `-1`，所以 `lo <= hi` 一开始就不成立，函数直接返回 `-1`，不会访问列表。

##### 重复元素

如果目标出现多次，函数返回的是*其中一个*匹配下标，不一定是第一个。

###### 调用方应当假定什么

只能假定返回的下标上确实是目标值。如果需要第一个或最后一个位置，请使用 `bisect_left` 这类变体：

```python
from bisect import bisect_left
index = bisect_left(items, target)
```

运行测试，每一项都应当通过：

```text nonumbers

test_single_item ............ ok
test_target_at_both_ends .... ok
test_target_missing ......... ok
test_repeated_values ........ ok
```

> [!WARNING]
> 传入未排序的列表不会报错，函数只会悄悄返回错误结果。这比程序崩溃更难被发现。
